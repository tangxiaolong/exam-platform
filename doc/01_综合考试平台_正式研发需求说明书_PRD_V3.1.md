# 综合考试平台正式研发需求说明书（PRD）

**版本：** V3.1  
**产品形态：** 微信小程序 + Java 微服务 + 独立运营后台  
**文档用途：** 产品评审、UI/UX 设计、研发估算、测试验收  
**说明：** 本文是可执行的首期需求基线。涉及微信平台资质、支付商户能力、考试合规要求的内容，须在项目启动时结合实际主体和业务场景复核。

## 1. 项目概述

### 1.1 产品定位
建设面向个人考生、培训机构、企业及行业组织的综合考试与学习平台，覆盖考试项目管理、题库学习、模拟练习、正式考试、成绩分析、课程服务和商业化交易。

### 1.2 建设目标
1. 支持多考试项目、多科目、多题型和多种考试规则。
2. 形成“选项目—学题练习—报名/购买—参加考试—查看成绩”的业务闭环。
3. 支持免费、会员、单科/题库售卖、课程售卖、机构采购和企业授权等商业模式。
4. 支持平台运营方统一运营，并为机构/企业提供租户级管理能力。
5. 保证考试过程可追溯、答题可恢复、交卷可判分、订单与权益可核对。

### 1.3 非目标
首期不承诺在线监考、人脸识别、复杂反作弊硬件接入、直播授课、题目自动生成和跨境多币种结算；可预留扩展点，立项后按实际需求排期。

## 2. 用户角色与权限

| 角色 | 核心职责 |
|---|---|
| 游客 | 浏览公开项目、免费内容、商品 |
| 注册考生 | 学习、练习、报名、考试、查看本人成绩 |
| 会员用户 | 使用会员范围内题库、课程或考试权益 |
| 机构管理员 | 管理本机构成员、课程/题库授权、考试组织和统计 |
| 企业管理员 | 管理企业员工、授权范围、考试计划和结果 |
| 题库编辑 | 维护题目、解析、知识点及版本 |
| 考试管理员 | 组卷、发布考试、处理考试异常、查看成绩 |
| 运营人员 | 商品、订单、会员、优惠、内容和运营数据 |
| 平台管理员 | 平台配置、租户、权限、审计及全局运营 |

权限遵循 RBAC；机构/企业数据按 tenant_id 隔离。高风险操作须记录操作人、时间、对象、变更前后内容。

## 3. 产品结构

### 3.1 微信小程序
- 首页：考试项目入口、搜索、推荐、公告、活动。
- 项目中心：项目介绍、科目、题库、考试安排、价格与权益。
- 学习中心：章节练习、顺序练习、随机练习、模拟考试。
- 错题/收藏：错题重练、收藏题、学习记录。
- 考试中心：考试列表、报名、准考信息、考试须知、在线考试。
- 成绩中心：成绩、答题详情（按权限开放）、错题解析、历史记录。
- 商城：会员、题库包、课程、套餐、优惠券、订单。
- 我的：个人资料、会员权益、订单、发票/售后入口、客服。

### 3.2 独立运营后台
- 工作台与数据概览
- 租户/机构/企业管理
- 用户与角色权限
- 考试项目、科目、知识点
- 题库、题目、解析、题目导入
- 试卷模板、组卷规则、试卷版本
- 考试场次、报名、考生名单
- 考试监控、异常处理、成绩发布
- 商品、套餐、课程、会员配置
- 订单、支付、退款、权益流水
- 内容、公告、消息模板
- 数据报表、导出、审计日志、系统配置

## 4. 核心业务需求

### 4.1 考试项目与科目
管理员可创建项目，维护名称、编码、简介、封面、适用对象、上下架状态、所属租户、展示排序。项目下配置科目、章节、知识点及其层级。项目、科目停用不得破坏历史考试记录。

### 4.2 题库管理
支持单选、多选、判断；后续扩展填空、问答、材料题。题目字段至少包括题干、选项、标准答案、解析、难度、知识点、标签、来源、状态、版本号。支持人工录入、Excel 模板导入、批量审核、批量上下架。导入须提供逐行错误反馈，不允许错误数据静默入库。

题目修改策略：已被正式试卷引用的题目不得直接覆盖历史快照；修改后形成新版本。题目删除采用逻辑删除，历史考试仍可回看原始快照。

### 4.3 学习与练习
支持按科目、章节、知识点练习；顺序、随机、错题、收藏练习；记录作答、正确率、练习时长和最近学习时间。断点续练应恢复到最近一次有效记录。练习答案与正式考试答案权限隔离。

### 4.4 试卷与组卷
支持固定试卷和规则组卷。规则包含题型数量、分值、难度区间、知识点范围、随机策略。组卷后必须校验题量、分值总和、题目可用状态和重复题。正式场次发布时生成不可变试卷快照。

### 4.5 考试场次与报名
场次配置考试名称、开始/结束时间、答题时长、允许进入时间、迟到规则、交卷规则、成绩发布时间、报名时间、报名限制、考试须知。报名需校验场次状态、时间、用户资格、购买/授权权益和名额。报名成功生成唯一准考记录。

### 4.6 在线考试
开考前展示须知并要求确认。服务端确定考试开始时间和截止时间；客户端计时仅用于展示。答题按题或按批次保存，服务端幂等接收。网络中断后允许恢复，恢复时以服务端已保存答案为准。到时自动交卷；用户主动交卷需二次确认。禁止客户端自行决定最终交卷时间。

### 4.7 判分与成绩
客观题自动判分。主观题预留人工阅卷、复核和成绩更正流程。成绩包含总分、各题得分、正确率、用时、提交状态、判分版本。成绩发布前可复核，发布后更正必须留痕并保留历史版本。成绩查看范围由考试规则控制。

### 4.8 商业化与权益
支持：
- 会员包月/包年；
- 题库或单科目购买；
- 单科/多科套餐；
- 免费内容 + 付费会员 + 课程；
- 机构采购；
- 企业授权。

商品购买成功后生成订单权益。权益应记录来源订单、适用项目/科目/内容、有效期、数量/次数、使用状态。订单支付成功与权益发放须通过可靠事件或事务消息实现，支持幂等补偿。退款按商品规则撤销或调整未使用权益；已使用权益的退款需走人工审核或按明示规则处理。

### 4.9 支付与售后
首期支持微信支付，具体支付能力以商户号和小程序主体资质为准。支付回调必须验签、核对商户、订单号、金额、币种和支付状态。前端支付结果不能作为最终成功依据。支持订单查询、超时关闭、退款申请、退款回调、对账和异常单处理。

### 4.10 消息通知
支持订阅消息、站内消息及后台通知。消息发送须校验用户授权、模板配置和发送频率；消息失败可重试并记录结果。不得将消息送达作为业务成功的唯一依据。

## 5. 关键流程

### 5.1 学习与考试
用户进入项目 → 选择科目 → 浏览题库/课程 → 练习 → 报名或校验考试权益 → 阅读须知 → 开始考试 → 保存答案 → 交卷/自动交卷 → 判分 → 成绩发布。

### 5.2 购买与权益
选择商品 → 创建待支付订单 → 发起微信支付 → 支付平台回调 → 验签及金额核对 → 订单置为已支付 → 发放权益 → 通知用户。回调重复、延迟或丢失时通过幂等和主动查单修复。

## 6. 核心规则与边界
1. 所有时间统一存储为 UTC 或带时区的标准时间，前端按业务时区展示；考试场次须明确时区。
2. 同一用户同一场次原则上仅允许一个有效准考记录；补考规则单独配置。
3. 考试开始后不得修改该场次试卷快照和考试规则快照。
4. 答题保存接口须支持幂等，重复提交不得产生重复答案版本或重复计分。
5. 交卷后禁止继续修改答案；管理员解封须记录原因和审批信息。
6. 多租户数据读写必须携带租户上下文，平台公共内容另行定义可见范围。
7. 价格、权益和考试规则变更不得影响已支付订单和已发布场次的历史快照。

## 7. 非功能需求
- 安全：HTTPS、密码哈希、接口鉴权、敏感信息脱敏、最小权限、审计日志。
- 性能：常规查询目标 P95 ≤ 500ms；考试答题保存目标 P95 ≤ 300ms（以压测环境和容量评估为准）。
- 可用性：核心考试时段需具备限流、熔断、降级、监控和应急预案。
- 一致性：支付、订单、权益、交卷、成绩等关键状态必须可追踪和可补偿。
- 兼容性：适配主流微信小程序基础库和常见移动终端。
- 可维护性：统一日志、链路追踪、指标监控、配置管理和版本发布。

## 8. 首期范围建议
P0：登录、项目/科目、题库管理、练习、固定试卷、考试场次、报名、在线考试、自动判分、成绩、商品订单、微信支付、权益、基础运营后台、租户隔离。  
P1：规则组卷、课程、会员套餐、优惠券、机构/企业批量授权、人工阅卷、报表增强。  
P2：在线监考、智能组卷、学习路径推荐、直播/互动课程、复杂企业组织同步。

## 9. 验收标准
- 用户可完成注册登录、项目浏览、题目练习和错题重练。
- 管理员可创建项目、科目、题库、试卷和考试场次。
- 报名校验资格、时间和权益，重复报名受控。
- 考试过程中答案可保存、断线可恢复、到时可自动交卷。
- 客观题判分准确，成绩可追溯到试卷和题目快照。
- 支付回调重复通知不重复发权益；金额不一致不得置为支付成功。
- 租户间数据隔离测试通过；越权访问被拒绝并记录日志。
- 核心流程有自动化测试、接口文档、部署手册和回滚方案。
