# 综合考试平台研发 WBS 与验收标准

**版本：** V2.1  
**用途：** 研发排期、任务拆分、联调计划、测试验收。

## 1. 项目阶段与工作分解

| 阶段 | 工作包 | 主要任务 | 交付物 |
|---|---|---|---|
| 0 需求确认 | 业务与范围 | 角色、流程、商业规则、首期范围确认 | PRD、原型、需求基线 |
| 1 技术准备 | 工程与环境 | 仓库、CI/CD、数据库、缓存、消息、对象存储 | 工程骨架、环境说明 |
| 2 基础能力 | 身份与租户 | 微信登录、用户、租户、组织、RBAC | 登录/权限接口 |
| 3 内容中心 | 项目题库 | 项目、科目、知识点、题目、导入审核 | 内容后台与 API |
| 4 学习中心 | 练习记录 | 练习模式、错题、收藏、进度 | 小程序学习功能 |
| 5 考试中心 | 试卷与场次 | 固定组卷、快照、报名、准考 | 考试管理功能 |
| 6 考试引擎 | 作答与判分 | 开考、答题保存、恢复、交卷、判分、成绩 | 考试闭环 |
| 7 商业化 | 交易权益 | 商品、订单、支付、退款、会员/题库权益 | 交易闭环 |

| 9 质量保障 | 测试上线 | 功能、性能、安全、兼容、灰度、回滚 | 测试报告、上线方案 |

## 2. 角色分工建议

- 产品：需求澄清、原型、验收口径、范围变更。
- UI/UX：小程序及后台交互、设计规范、切图资源。
- Java：领域模型、接口、数据库、业务逻辑、集成和自动化测试。
- 小程序：页面、状态管理、断点恢复、支付和消息交互。
- Web：运营后台页面和权限控制。
- 测试：用例、接口测试、兼容、性能、安全和回归。
- 运维：环境、发布、监控、备份、容量和应急预案。

## 3. 关键里程碑（建议）
- M1：需求和原型评审通过。
- M2：基础工程、登录、租户和权限完成。
- M3：题库、练习、试卷和场次完成。
- M4：考试作答、交卷、判分、成绩完成。
- M5：订单支付和权益完成。
- M6：全链路联调、压测、安全测试和试运行完成。

具体工期需在确认团队人数、既有组件复用情况、并发指标和 UI 范围后估算，不在需求未冻结前承诺固定日期。

## 4. 核心验收用例

### 4.1 身份与租户
- 微信登录成功后建立平台用户身份；同一微信身份重复登录不重复创建用户。
- 客户端伪造 tenant_id 不得访问其他租户数据。
- 角色无权限时接口返回明确无权限错误并记录审计。

### 4.2 题库与练习
- 题目导入成功/失败行均有结果报告。
- 题目版本更新后，历史考试快照内容不变。
- 练习答案、解析按业务配置展示；错题记录统计正确。

### 4.3 考试
- 报名时间外、场次关闭、无资格或无权益时不能报名。
- 同一用户重复报名按规则返回既有记录或明确错误。
- 开始考试后服务端生成唯一 deadline_at。
- 网络断开后恢复考试，已保存答案完整。
- 过期答案保存被拒绝；到时自动交卷只执行一次。
- 主动交卷重复请求不重复生成成绩。
- 客观题评分符合题型规则，成绩可追溯到快照版本。

### 4.4 交易与权益
- 客户端修改商品价格不能影响服务端订单金额。
- 支付回调验签失败、金额不一致、商户不匹配均不得标记支付成功。
- 同一支付通知重复推送不重复发放权益。
- 退款状态与权益调整有完整流水。

### 4.5 稳定性与安全
- 集中开考压测覆盖目标并发及突发流量。
- 答题保存接口具备幂等、限流和超时保护。
- 文件上传限制类型、大小并进行安全检查。
- 管理后台敏感操作有审计记录。
- 日志中不出现密码、支付密钥、完整敏感个人信息。

## 5. 测试策略
- 单元测试：领域规则、状态机、判分、金额计算、权益幂等。
- 集成测试：数据库、Redis、消息队列、微信支付沙箱/测试配置。
- API 测试：正常、异常、越权、重复请求、并发冲突。
- 端到端：登录—学习—报名—考试—成绩；下单—支付—权益。
- 性能测试：集中登录、集中开考、答题保存、自动交卷、成绩查询。
- 安全测试：鉴权、越权、重放、注入、文件上传和敏感信息泄漏。

## 6. 发布准入条件
1. P0 需求验收通过，无阻断级缺陷。
2. 核心接口具备监控、告警和 trace_id。
3. 数据库已备份，迁移脚本经验证，回滚方案可执行。
4. 支付、订单、权益对账通过。
5. 考试场次、答题、自动交卷及成绩链路演练通过。
6. 运维值守、故障联系人和应急预案明确。
