# 12 · 组卷的知识点范围

> 对应 Step 5 第三组。代码：`modules/paper/PaperService`、`modules/question/QuestionService`；
> 迁移：`V15__paper_rule_knowledge_point.sql`。

## 一、动手前先纠正一个前提

看代码才发现，**难度过滤早就存在**：`exam_paper_rule.difficulty` 一直有，`randomByRule` 也在按它过滤。
真正缺的是两件不同的事：

1. **按知识点抽题**——完全做不到，`qb_question` 与 `exam_knowledge_point` 之间没有任何关联列；
2. **难度配比**——一条规则只能指定一个难度，无法表达「简单 3 道 / 普通 5 道 / 困难 2 道」。

第 1 条是硬阻塞，必须先补数据层。

## 二、四个建模决定

| 决定 | 原因 |
| --- | --- |
| 题目挂**单个** `knowledge_point_id`，不建多对多 | 一题多知识点会让「覆盖度」重复计入，而覆盖度是这功能唯一的意义；多标签需求走已有的 `tags` 列 |
| 列可空 | 存量题目都没标注，`NOT NULL` 会让迁移直接失败 |
| **未标注 ≠ 匹配任意知识点** | 把 NULL 当通配会让覆盖度失真。指定知识点后未标注的题一律不抽 |
| 一条规则只表达一个知识点 | 数组模式下抽不满时只能报「知识点范围共需 5、可用 2」，定位不到是哪个；一条规则一个知识点才能报「知识点 3 需要 5、可用 2」 |

第三条有一个直接后果：**配了知识点范围，就必须先给题目补标注**，否则抽不到题。这是正确行为，但必须在报错里讲清楚——见第四节。

## 三、规则的去重键

原键是 `type|difficulty`。加上知识点后必须变成 `type|difficulty|knowledgePointId`，
否则「单选×普通×知识点 C」和「单选×普通×知识点 D」会被判成重复规则直接 400，
而这恰恰是新功能最常见的用法。

这一条有专门的回归用例（`differentKnowledgePointsAreNotDuplicateRules`）。

## 四、报错必须区分两种「抽不到题」

| 情况 | 提示 |
| --- | --- |
| 限定了知识点，该知识点下没题 | `知识点 3 下可用题目不足：需要 3 道，实际 0 道；请确认题目是否已标注该知识点` |
| 不限知识点，题库整体不够 | `规则「SINGLE/HARD」需要 3 道题，题库当前可用 0 道` |

共用一句文案的后果是：运营看到「可用 0 道」就去加题，而真正该做的是给已有的题补标注，方向完全相反。

`KnowledgePointPaperTest` 里对这句文案做了内容断言（`contains("知识点")`、`contains("标注")`），
这也是给测试基类新增 `errorMessage()` 的原因——**错误码只能证明「拒绝了」，证明不了「提示有用」**。

## 五、开关：`question.knowledge-point.required`

默认 `false`。打开后，**未标注知识点的题目不允许从 DISABLED 改为 ENABLED**。

选在「启用」而不是「创建」时拦截，是因为：存量有大量未标注题目，创建时强制会卡住现有录题流程；
而「启用」是进入可组卷池的最后一道门，在这里拦截既能保证池子干净，又不影响存量编辑。

测试覆盖了完整救援路径：开关关→可启用；开关开→被拒；补标注→可启用。

## 七、难度配比（已实现，V16）

规则可以按权重分配多个难度：`{"EASY":1,"NORMAL":2,"HARD":3}`。

### 1. 权重不是百分比

`1:2:3` 与 `20:40:60` 表达同一件事，权重之和不需要等于任何数。运营不必先算百分比，也就不会出现「33/33/33 加起来不到 100」这类问题。

### 2. 存储格式是 `EASY:2,NORMAL:5`，不是 JSON

列注释写的是 JSON，实际存的是逗号分隔的 `难度:权重`。原因：`PaperService` 里没有可靠的 JSON 映射入口，而这个格式解析只需一次 `split`，不引入依赖。写入时用 `TreeMap` 保证顺序固定。

**修改 V16 的列注释是有风险的**——迁移已应用，改动会导致 Flyway checksum 不匹配。所以以本节为准，不改 SQL 文件。

### 3. 四舍五入后差值补给 NORMAL

`count=7`、配比 `1:1:1` 算出 2.33/2.33/2.33，四舍五入得 6 道，差 1 道补给 NORMAL，最终 2/3/2。

不按「余数从大到小」补：那种算法依赖当次查询结果，同样的规则在不同时间抽出的题数会飘。考试组卷必须可复现。

### 4. 与 `difficulty` 互斥

同时给出时直接 400。否则「规则说 HARD、配比又给 EASY:2」是未定义行为，只能靠猜。

### 5. 测试

```text
DifficultyMixPaperTest
  · 权重整除 → 1/2/3，总数 6
  · 除不尽 → 总数 7，分布 2/3/2（差值给了 NORMAL）
  · difficulty 与 difficultyMix 同时给 → COMMON_BAD_REQUEST
```

## 七之二、知识点归属校验（已实现）

题目保存时校验 `knowledgePoint.subjectId == question.subjectId`，并拒绝不存在的知识点。

不做的后果：挂错科目的知识点不会报错，只会让这道题在任何知识点范围里都抽不到，而报错指向「该知识点可用 0 道」——几乎不可能联想到是科目挂错了。
